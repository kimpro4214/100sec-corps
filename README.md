# 100초 군단

100초마다, 내가 키운 빌드가 다음 라운드의 적이 되어 돌아오는 뱀서라이크.

- **플레이:** (웹 빌드 링크)
- **엔진:** Godot 4.7 (GDScript, 웹 export)
- **기간:** 2026-11-07 ~ (v0.9.2)

## 어떤 게임인가

뱀서라이크의 재미는 강해질수록 더 많은 적을 쓸어버리는 데 있다. 이 게임은 여기에 규칙을 하나 더한다. **라운드가 끝날 때의 내 빌드가 저장되고, 다음 라운드부터 그 빌드를 쓰는 "과거의 나"가 적으로 나온다.**

그래서 레벨업 선택지를 고를 때 "지금 나에게 좋은가"와 함께 "다음 라운드에 이걸 상대해야 한다"를 같이 따지게 된다.

- 한 판은 5라운드, 라운드마다 100초다. 70초에 보스 방 포탈이 열린다.
- 메인 무기 4종: 마력탄, 가시 오라, 낙뢰, 시간의 실. 5레벨에 각성한다.
- 과거의 나는 지난 라운드의 내 이동 경로를 그대로 걷는다.
- 보스 5종, 웨이브, 상자·룰렛·제단 같은 상호작용, 처치 수로 충전하는 궁극기가 있다.

**조작:** 이동 WASD / 방향키, 공격 자동, 레벨업 선택 1·2·3, 궁극기 Space, 일시정지 Esc

### 시간의 실

"남들과 다른 무기가 하나는 있어야 한다"는 문제에서 나온 고유 무기다. 조준 없이 걸어온 자리에 실이 남고, 실 끝이 실에 다시 닿아 고리가 닫히면 안쪽의 적이 터진다. 뱀서라이크의 유일한 조작인 이동이 곧 공격이 된다.

과거의 나는 내 경로를 걷기 때문에, **이번 라운드에 내가 그린 고리가 다음 라운드에 적의 함정으로 다시 닫힌다.** 게임의 핵심 규칙과 무기가 맞물리도록 설계했다.

## 만드는 방식

사람, AI, 봇이 맡는 일을 나눴다.

| 누가 | 하는 일 |
|---|---|
| 사람 | 문제를 정의하고, 직접 플레이해서 재미를 판단하고, 최종 결정을 내린다. |
| AI | 기획 선택지와 구현 초안, 수치 조정안을 낸다. |
| 봇 | 실제 게임과 같은 규칙으로 수백 판을 돌려 밸런스를 잰다. 재미는 판단하지 않는다. |

한 번의 반복은 이렇게 돈다.

```
직접 플레이 → 문제 정의 → AI가 선택지·구현 → 봇 측정 → 사람이 채택 여부 결정 → 기록
```

이를 위해 구조를 두 가지로 잡았다.

- **규칙과 화면 분리:** 게임 규칙은 `legion/sim/`에만 있다. 화면과 봇이 같은 코드를 돌리기 때문에 봇의 측정값이 실제 게임에 그대로 맞는다.
- **수치는 데이터로:** 밸런스 수치는 모두 [`legion/data/balance.json`](legion/data/balance.json)에 있다. 수치를 바꾸면 코드 수정 없이 바로 봇으로 확인할 수 있다.

모든 결정은 "누가 제안했고 누가 골랐는지"와 함께 [기획서](docs/legion_design.md)에, 측정 수치는 [AI 실험 로그](playtest/ai_log.md)에 남긴다.

## 봇과 사람이 다르게 본 것

봇 수치를 그대로 따르지 않은 사례들이다. 이 게임에서 가장 많이 배운 부분이다.

**1. 첫 외부 플레이테스트: "너무 쉽다"**

봇 승률은 목표(30~50%) 안이었는데, 처음 해 본 사람은 쉽다고 했다. 어디서 난이도를 올릴지 정하려고 레버를 하나씩 바꿔 가며 봇을 돌렸다.

| 바꾼 값 | 생존형 봇 승률 |
|---|---|
| 기준 | 50.0% |
| 적 체력·웨이브 증가 | 45.3% |
| 라운드 회복량 감소 | 48.0% |
| 과거의 나 피해 0.45 → 0.9 | **25.3%** |

적 체력이나 웨이브는 승률을 거의 못 움직였고, 과거의 나의 피해만 크게 움직였다. 이 게임의 핵심 위협이 과거의 나이므로 어려움도 여기서 오는 게 맞다고 보고 0.9를 적용했다. 3라운드 도달률은 그대로라 초반은 두고 후반만 어려워진다. 봇 목표도 사람 기준에 맞춰 15~30%로 낮췄다.

**2. 가시 오라: 봇은 가장 약하다고, 사람은 가장 쉽다고**

봇 측정에서 오라 특화 승률이 가장 낮았지만, 직접 해 보니 오라가 가장 깨기 쉬웠다. 봇이 근접 무기를 서툴게 다룬다고 판단해 수치는 바꾸지 않았다. 무기 간 격차는 사람 플레이를 기준으로 본다.

**3. 시간의 실: 봇이 잴 수 없는 것을 따로 재기**

기록용 봇은 적 무리를 노려 고리로 가두지 못한다. 그래서 보스 둘레를 도는 봇을 따로 만들어 고리의 가치만 쟀다.

| 봇 | 2라운드 보스 처치 | 승률 |
|---|---|---|
| 도망치며 실로 베기만 | 61.4초 | 59.3% |
| 보스에 바짝 붙어 돎 | 31.9초 | 0.0% |

고리로 가두면 보스 처치 시간이 절반으로 줄지만, 붙어 있는 만큼 위험하다. "안전하게 느리게 vs 위험하게 빠르게"라는 선택이 실제로 있다는 걸 확인했다. 그 사이를 사람이 즐겁게 타는지는 플레이로 판단한다.

## 현재 밸런스 (v0.9.2, 봇별 150판)

| 봇 | 승률 | 5라운드 도달 |
|---|---|---|
| 생존형 | 25.3% | 64.7% |
| 각성 지연 | 41.3% | 78.0% |
| 마력탄 특화 | 22.7% | 60.7% |
| 가시 오라 특화 | 1.3% | 40.0% |
| 낙뢰 특화 | 22.0% | 61.3% |
| 시간의 실 특화 | 39.3% | 88.7% |

원본 데이터는 [`playtest/legion/`](playtest/legion/)에 있다. 판별 결과, 라운드별 보스 처치 시간, 사망 원인, 레벨업 선택 기록이 들어 있다.

## 실행

```bash
# 게임
godot --path .

# 규칙 테스트
godot --headless --path . --script res://legion/test_thread.gd

# 밸런스 봇 (결과는 playtest/legion/에 CSV로 저장)
godot --headless --path . --script res://legion/bot_runner.gd -- --runs 150 --seed 1
```

## 폴더 구조

```
legion/
  sim/       게임 규칙 (화면과 봇이 공유)
  game/      씬, 렌더링, UI, 연출, 사운드
  data/      밸런스 수치
  bot_runner.gd
docs/        기획서
playtest/    봇 결과와 AI 실험 로그
capture_deck/  초기에 함께 만들다 접은 덱빌더 프로토타입
```

## 다음 가설

- AI가 새 보스 데이터를 쓰면 봇이 승률 기준 통과 여부를 자동으로 판정한다. 사람은 통과한 보스만 플레이해서 재미를 판단한다.
